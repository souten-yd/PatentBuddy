# 公開承認済み資料専用API（v0.5.4）

管理者が公開済みで共有の利用許諾がある資料だけを承認する。NASとControlDeckのprivate業務APIと独立した権限であり、自動的なクラウドLLM送信機能ではない。

1. `POST /api/v1/publications/preview` に文献IDと原文内の抜粋を渡す。タイトル・公開番号・抜粋の全項目を返す。本文を変更/切り詰めない。
2. 管理者が全項目と利用許諾を確認し、`POST /api/v1/publications` に同じ文献ID・抜粋、`preview_token`、`confirm_public:true`を送る。
3. 10分有効のメモリ上の鍵で署名したプレビューは文献版と全表示項目に結び付く。変更/期限切れ/サーバー再起動で再確認が必要。プレビュー自体は永続書込みなし。
4. 文献更新トリガーが既存承認を無効化する。元の本文に戻しても再承認なしに公開を再開しない。
5. 管理者発行の`published`トークンは`/api/v1/public-catalog/search`と`/api/v1/public-catalog/{id}`に限定。private資料、設定、MCP、debug/exportへアクセスできない。LAN pairingで公開用tokenを作れない。loopback以外はTLS必須。

公開抜粋は別snapshotとして保存し、原文の全体・メタデータ・内部IDは返さない。文献更新に伴う無効化書込みは、変更後に秘密を公開しないために必要。承認・取消・監査時以外のカタログ検索/プレビューは読み取りのみ（認証のlast_seenは既存ポリシー）。

検証: 公開API14テストでプレビュー必須・内容差替え・版変更・期限切れ・再起動・原文復元/削除・全非公開routeの403・CSRF/Origin・token失効・TLS条件・LLM出口0件を確認。検索とプレビューのDB更新は0。FTS5代替経路も検証した。

証明書を検証する実HTTPSクライアントで公開抜粋取得とMCP拒否を確認。Chromeの1280/390pxでプレビュー・編集による無効化・承認・専用token発行/利用を確認し、横溢れ・JSエラー・外部リクエストは0。QNAP実環境のTLSは未検証。
