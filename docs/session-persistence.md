# ログイン保持・更新確認・パスキーの安定性

PR #11をmain v0.5.2へ統合して検証中。SHA-256セッションIDのみ永続化し、再起動/期限切れ/ログアウト/パスワード変更を検証する。既存QPKG ID、データ、Cookie、パスキーRP IDを維持。

更新確認POSTが本文を読まずHTTP/1.1接続を再利用し、続くリクエストを `{}GET` として解釈して501を返す不具合を実HTTPテストで再現。未読本文がある応答は接続を閉じる。一般リトライは追加しない。QTS固有の原因やiPhone実パスキーの再現は未検証。

GitHub改名で旧版v0.5.1の資産URL検証が失敗することも実際に確認。現行の正規リポジトリ名に修正するが、既に配布された旧クライアントは初回のみ手動更新が必要。旧名の任意URLを許す制約緩和は行わない。
