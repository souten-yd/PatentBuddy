# 手動 SQLite バックアップ

QnapLibrary の**データベース**を、停止せずに一貫性のあるスナップショットとして作成します。v0.5.0 では手動のみ、差分・定期実行・Webからの復元は行いません。

## 実行方法

管理 Web の「設定 > バックアップ > 今すぐバックアップを作成」から実行します。管理者セッション＋CSRF トークンが必要です。API は `GET /api/backups`（一覧）と `POST /api/backups`（作成）のみで、デバイストークンでは呼び出せません。

保存先はデータフォルダの `backups/qnaplibrary-YYYYMMDDTHHMMSSffffffZ.sqlite3`。ファイルは 0600、ディレクトリは 0700、失敗時は一時ファイルを掃除します。SQLite `VACUUM INTO` 後に `PRAGMA quick_check` を行い、成功したものだけを最終名に移します。バックアップ中は SQLite の書き込みが一時的に待機する場合があります。空き容量の予備として最低 64 MiB を確保します。

**重要:** この機能で保存するのは `library.sqlite3` だけです。認証・API キー・アプリ設定が入る `settings.json` と `secrets.json` は含みません。NAS の HBS3 等を使い、**データフォルダ全体**を別のディスク／場所にもバックアップしてください。同一 NAS 内のスナップショットは NAS 全損に備えられません。バックアップには機密データが含まれるため公開しないでください。

## 復元（オフライン）

1. QnapLibrary を停止し、別途データフォルダ全体の退避を取ります。
2. 保存済み SQLite を `library.sqlite3` にコピーします。停止後に既存の `library.sqlite3-wal` と `library.sqlite3-shm` が残っていれば、**元の DB と組にして保全**し、スナップショットと混在させないでください。
3. ファイル所有者・権限をアプリ実行ユーザーに合わせ、再起動して `/api/health` と文書検索を確認します。Qdrant 利用時は復元した SQLite に合わせて再同期します。

復元は自動化していません。定期実行・保存世代管理・設定を含めた完全バックアップは次の拡張候補です。
