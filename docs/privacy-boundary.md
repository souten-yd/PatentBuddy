# 機密保護境界（QnapPatentBuddy）

**原則:** 未公開のアイデア・テーマ・発明届・請求項草案・明細書・図面・競合比較・検索式・調査履歴・参考文献との対照内容は、出願前/未公開の機密データ。外部サービスへ送らない。公報/規格の一般公開文献でも、何を調べたかという検索語や特定の引用組合せは機密になり得る。

## ローカルLLMの利用条件（全て満たす）
1. エンドポイントが実際にデバイス上でモデルを実行しており、**OpenRouterや他のクラウドへのプロキシではない**ことを管理者が自分で確認。
2. 設定画面の各プロバイダで `local_only_verified` にチェック。既存の QnapAssistant は同NAS接続でも内部で外部APIへ転送する可能性があるため**初期状態では未確認**。
3. URL は `localhost` / `127.0.0.1` / `[::1]` の直接接続。リダイレクトと環境変数 HTTP(S)_PROXY を無効化。DNSホスト名、パブリックIPは受け付けない。
4. 別マシンの推論サーバーを許す場合は、設定 `privacy.allow_lan_https_llm=true` を管理者が明示して、RFC1918/Tailscaleの**IPリテラル+TLS証明書検証**を使用（LAN HTTPは不可）。推論サーバーの上流クラウド転送がないことも自分で検証。
5. 機密データを処理する `chat`/`chat_stream`/`embeddings`/`rerank` は上記のみ利用可能。プロバイダ未確認なら失敗させ、キーワード検索を残す。通常時にOpenRouterキーが設定されても**自動埋め込みが開始されない**。

※ 接続先URLだけでモデル内部の動作を証明することはできない。さらに強い保証にはホスト側ファイアウォールで外部インターネットへの送信を制限し、QnapAssistant/ローカルLLMの設定も検査する必要がある。管理者が偽のURLやクラウド中継を設定した場合、アプリの制限だけでは100%の保証はできない。

## 外部AIで許可すること
`POST /api/v1/public-patent-guidance` は、予め登録したテーマ（新規性・進歩性・権利範囲・FTO一般論・出願戦略）から**サーバー固定の質問文**を生成する。ユーザー自由入力、案件タイトル、検索結果、文書データ、チャット履歴、付属の追加JSONは参照しない。LLM出口で**固定テンプレートとの完全一致**を確認できた場合のみ外部に出せる。`POST /api/llm/test` も固定の「OK」検証文字列のみ。例外指定だけでは遮断を回避できない。

OpenRouterで提供されるZDRやプロバイダ設定は**補助**であり、未公開の発明の送信を認めるものではない。OpenRouterは選択したプロバイダへ入力を転送し、保存・利用規則はそれぞれ異なり得る。公開ガイドの結果も法的結論ではない。

## その他の漏えい対策
- **自動ウォッチ:** 既存レコードは `params.public_only_confirmed=true` を明示していない限り停止。公報の公開検索語であることを人手で確認。ウォッチの登録/実行/更新を管理者操作に限定。隠れた自動実行や未承認の検索語の再送信なし。
- **手動コネクタ:** `POST /api/v1/connectors/{name}/run` は管理者＋ `public_query_confirmed:true` が必要。外部APIへクエリが送られると明示。
- **調査ジョブ:** 未公開テーマに由来する GDELT ニュース検索は禁止。外部へ送らないローカルRAGとローカルLLMのみ使用。
- **通知:** SMTP/Slack/Discord/Webhookには「NASで確認してください」という汎用文言のみ。発明名・期限の案件名・レポート本文・検索結果・URLを含めない。
- **Qdrant:** ベクトルも情報を推測され得るので、同一NASのloopbackに限定。通信は環境プロキシを使わず、HTTPリダイレクトを追わない。
- **保存:** 通常のSQLiteと認証の保存場所は従来通り。機密APIの結果を外部へ同期したりメールで送らない。バックアップとデバッグ情報の扱いは管理者が保護。
- **責任境界:** 物理的なデータ持ち出し、NASの他プロセス/OSの侵害、ユーザーの明示的なファイル共有、任意のサードパーティLLMプロキシ内部まではアプリ単独で防御不能。

## 利用前の確認
機密性を最大に保ちたい場合：インターネット接続を遮断したローカル推論エンジンをNAS/信頼できるPCに配置。管理 Web > AI のプロバイダ設定で「ローカル専用確認済み」を選択。クラウド/自動ニュース検索を使わず、特許案件のブレスト・請求項はこのLLMで実行。新規利用前にテストで送信0件と、QNAP実機の設定を確認する。
