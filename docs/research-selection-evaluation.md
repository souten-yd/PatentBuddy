# 調査候補の絞り込み方式の比較と採用判断

2026-11-11。公式検索指針と既存実装の比較による設計評価。実特許の関連性正解セットによる精度評価は未実施であり、以下を精度向上の実測結果と呼ばない。

## 比較

|方式|利点|失敗しやすい点|判断|
|検索の上位N件を取得|CPU/通信が小さい|同一ファミリー・言い換え・分野偏り、取得元順位への依存|比較用baseline。無断切詰めとしては採用しない|
|ヒートマップのセルを除外してN件以内へ|人が範囲を理解し操作できる|複数分野に属する発明を丸ごと落とす、少数セルの重要発明を見落とす|採用。ただし解除可能なfilterとして扱い単独の選定根拠にしない|
|全候補をLLMで採点して上位N件|柔軟な目的評価|推測・モデル変動・処理時間・NAS/GPU負荷、未取得候補の見落としは救えない|単独方式は不採用|
|段階検索＋ファミリー整理＋候補限定rerank＋多様性を考慮した選定案＋除外再確認|取得量を抑えつつ、ユーザーが取りこぼしと偏りを確認できる|正解集合を用いた評価と複数段階の状態管理が必要|採用方針。関連性モデル/重み/配分は実測後に決定|

## 採用する流れ

- 最初に目的を分ける。技術俯瞰、先行技術、権利比較では期間・国・代表公報の優先条件が異なる。既定は技術俯瞰で、法的な網羅性を保証しない。
- キーワードと同義語で候補を探し、実際に関連した公報のIPC/CPC・引用を利用して段階的に拡張する。外部に出す追加検索式は送信前表示/承認済みsnapshotに結び付け、機密目的から無断生成して送らない。検索回数・候補数・期間・bytesを別々に制限。
- 同一公報を統合し、ファミリー別にまとめる。明示的に選ばれた基準文献をpinできる。pin数が上限を超える場合は黙って解除せずエラー。
- NASでは書誌の索引・集計・ID集合によるfacetを行い、PCで限定候補をrerankする。LLMは分類根拠・絞り込み理由を生成し、スコア自体を特許性と呼ばない。
- 選定案は関連性だけでなく対象機器/検知手法/年代の偏りも表示。多様性優先で低関連公報を強制採用しない。多様性方式（MMRや分類層化等）の具体的採用はbaseline比較後に決める。
- ヒートマップは「非表示」「今回の取得対象から除外」「保留」を区別。重なるセルは公報ID集合で集計。低信頼/未分類を自動削除しない。除外理由と解除操作を保持する。
- ダウンロード前に境界候補・未分類・除外集合の少数例を確認できるようにする。例示は網羅保証ではない。条件を変えるとsnapshotを再確定し、前回承認で新しい対象を取得しない。
- 上限内の選定案を提示し、ユーザーの取得開始操作またはその条件への事前承認後に取得。継続調査は差分書誌→新規/更新公報の候補提示とし、毎回全PDFを取り直さない。

## 実データ評価の契約

パワエレ候補10件は現在検索抜粋だけで、全てを関連性の正解とみなさない。原本/請求項を確認した正解集合と明らかな近接非対象を用意し、同じ候補集合・取得予算で比較する。

1. キーワード順位、候補限定rerank、rerank＋偏り対策を比較。検索式の改善に使った資料と評価用資料を分ける。
2. 既知関連公報の回収率、precision@N、ファミリー重複率、対象/手法のカバレッジ、未分類率、ユーザーの修正数を測定。候補外の公報に対するrecallは不明と明示。
3. 実PDF取得数/bytes、API呼出数、取得時間、PC推論時間/モデル版、NAS CPU/RSS/物理I/O/P95も記録。
4. 新方式が既知重要文献を失ったり処理負荷だけ増やす場合は採用しない。精度差が不明なら単純な方式を既定とし、候補提示として比較可能に残す。
5. 無料枠・API登録要否・取得不可資料を表示。PATENTSCOPEブラウザの自動取得禁止を回避する実装はしない。
