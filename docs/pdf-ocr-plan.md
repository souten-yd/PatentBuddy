# PDF取り込み・OCR

ユーザー要求: ダウンロード済みの特許PDFに加え、文字がないPDFも必要時に読み取る。

- PC側PatentBuddyで実行。ControlDeck Filesの読取grantから選択した原本だけを取得し、Host JobとCPU資源leaseを使用する。任意path/command APIは作らない。
- Popplerのページ単位テキスト抽出を先に使う。空白/少量のページや画像の混在するページだけローカルTesseract（jpn+eng）へ回し、ページ指定の強制OCRも許可する。図面ページが文章に化けたと推定せず、OCR結果を未確認として表示する。
- 原本SHA-256、ページ番号、抽出方法、tool版、OCR単語信頼度/低信頼箇所を保存する。原本とページ画像/図の表示から確認できること。LLMに画像の読み取りを黙って代替させない。
- PDFサイズ/ページ数/描画画素数/文字数/同時実行/時間/一時ファイル容量に上限を設ける。パスワード付き・破損・tool未導入は明示エラー。途中失敗を成功扱いせず、キャンセルで子processを止める。
- 原本と抽出結果の正本はResearchDataHubだけ。Addonの一時コピーはジョブ終了で破棄。書込専用の狭い取込認証を設計し、既存ro/analysis権限から一般rwへ広げない。
- 保存は原本hashにより冪等化し、原本/ページ根拠のsnapshot復元まで確認する。追加ディスク容量/I/Oを測定して記録する。
- 原本から抽出した内容を、Hostのlocal_only対応LLMで要約・請求項確認へつなぐ。既存の公開専用権限/機密境界を維持する。

実装はPC側のHost Files/Jobs/CPU leaseと取り込み画面へ接続済みです。原本、抽出版、埋め込みラスター画像を正本SQLiteへまとめて保存します。取り込みの応答が途切れた場合は抽出版hashで保存結果を照合し、原本を再登録したと決めつけません。全抽出版を削除した時だけ共有原本/画像も削除します。snapshotにはこれらのBLOBも含まれます。

入力上限は50MiB/200ページ/本文100万文字。画像は200点、1点2MiB/1600万画素、合計32MiB。抽出工具の処理時間・RAM・ファイルサイズを制限し、上限超過時は部分成功として保存しません。画像閲覧は1枚ずつで、ページを切り替える際は前の表示URLを破棄します。ベクトル図形や図番号の自動認識は対象外です。

ジョブ再開はファイルの再選択と原本hash照合が必要です。保存確認待ちやHost終端同期待ちは先に状態確認します。処理履歴から除外しても正本資料は削除しません。Hostのlease照合API（ControlDeck PR350）が必要です。原本等の試験データと本番DBを分離した実Host UI受入はHANDOFFに記録し、署名配布・導入済み受入の完了とは区別します。
