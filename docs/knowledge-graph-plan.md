# PatentBuddy 知識資産化・発明エッセンス再利用計画

状態: **計画・設計のみ（2026-11-17）**。この文書を追加しただけでは機能は実装・配布されない。詳細な設計契約は [knowledge-graph-design.md](knowledge-graph-design.md) に置く（同じdocs-only PRで追加）。既存 [PR #23 / evidence-graph.md](https://github.com/souten-yd/PatentBuddy/blob/feat/evidence-graph/docs/evidence-graph.md) は **Draft PR #23 の作業ブランチにのみ存在**し、mainに反映されるまでは正式なruntime機能と扱わない。

## ビジョンと価値
- 検索語・技術課題・特許案・請求項・PDFを起点に公式取得済み文献や登録文献を調査し、原文根拠に紐付いた「課題→原因/制約→解決原理→作用機構→実装→効果」を**再利用可能な知識**として蓄積する。
- Obsidianのような**双方向ナビゲーション可能な意味付き知識マップ**を提供する。単なる文献間リンクでなく、解決原理・適用条件・反例・別領域への適用候補まで扱う。
- 次の特許調査で蓄積知識を横断検索し、既知技術の比較、異分野への転用仮説、組合せ案、改良案、新規発明候補を**明示操作で**生成して再調査する。
- 保存文献数ではなく「原文と区別された説明可能な知識」「実案件への再利用」「出典追跡と訂正」が成果指標。AI生成アイデアは既知技術・特許性確定とみなさない。

## 機能範囲
1. **文献・案件の入力**: 既存ResearchDataHubの文献、PDF/OCR・請求項、公開規格/論文等。新規取得は公式API/許諾済み経路のみ。外部検索語の送信は公開確認後のみ。
2. **構造化抽出**: 技術課題、原因、制約、技術原理、作用機構、構成要素、技術効果/測定条件、適用条件、限界、代替、非特許文献・請求項への根拠を生成。
3. **知識ノート**: 公報の要約と独立した技術エッセンスカード。正規化候補/同義語/上位概念を提示し、既存知識との統合を人が承認する。異説・適用条件・矛盾を保持。
4. **根拠付き知識グラフ**: 文献→知識要素→原理/効果→別分野の応用・アイデア、方向付きの型付き関係。原文からの事実、AI推論、ユーザー創造を混同しない。
5. **探索・再利用**: キーワード/ベクトル/分類/原理の類似度/1〜2hopの限定グラフ探索を組み合わせ、検索理由を説明。選択したノードから発明案を複数提案し、先行技術調査・請求項比較へ接続。
6. **可視化**: グラフビュー、カード詳細、原文/段落の行き来、検索フィルタ、由来・状態・適用条件の表示、部分マップ・モバイル操作。
7. **知識の学習**: 人の承認/訂正/不採用と実験結果を版付きで記録。AI候補を無断採用・無断上書きしない。モデル再処理時も既存の人手判断を上書きしない。

## 情報の3層と判定上の境界
- **Source/Evidence**: 正本原文・ページ/段落/請求項・文献版・ハッシュ・位置・アクセス権・出典。論理的な含意までは「引用が存在する」だけで保証しない。
- **Knowledge**: 課題/原理/実装/効果などの再利用候補。statementごとに事実根拠か推論か、review、stale、confidence（校正された確率とは限らない）を保持。
- **Idea**: 組合せ・改良・異分野応用・請求項候補。検証計画・期待効果・制約・依存する知識を保持。発明性・新規性・進歩性・FTOの法的結論とは別。

## 互換性・禁止事項
- ResearchDataHubの**唯一の正本SQLite**に保持し、PCのControlDeck PatentBuddy側にはジョブ状態・再構築可能なキャッシュだけ。稼働中SQLiteのSMB/NFS共有、別の知識正本、無制限Graph探索を禁止。
- 未公開発明/調査クエリ/推論内容をクラウドLLMへ送信しない。検証済みlocal-only AIのみ。公開文献の内容が公開でも、何を検索・結合したかは機密扱い。検索APIへの外部送信も個別承認。
- オリジナル文献の改訂で根拠依存カード/辺/アイデアをstaleにして**過去の承認を自動復活させない**。推論を事実へ自動昇格しない。根拠がないなら未確認/仮説で表示。
- 旧QPKG ID `QnapLibrary`、内部package `qnaplibrary`、17871、データパス、WebAuthn RP ID、既存API、Host v2契約を維持。
- `ui.html` default、Vue read-only・not default、backend authoritative、`level_0_manual_only`、no executionを維持。mutation/execution/autonomous、raw source serving、fallback/redirect、server起動時npm buildを追加しない。
- このdocs-only PRでは**コード/manifest/runtime/API/DB/CI/バージョンを変更しない・Releaseしない**。

## 品質ゲート
- 知識抽出の根拠正確性・見落し・誤統合・異分野提案の妥当性を、人間が作った正解データで評価する（Recall@k、Precision@k、unsupported statement率、誤統合件数、stale見落し件数）。
- 陰性例: 引用偽造、版変更、権限漏れ、推論の事実化、未承認モデル、途中取消/保存応答消失、巨大グラフ、入力上限、重複取込をテスト。
- 原文改訂・人手review・削除時以外の通常GET/閲覧/アイドルで不要な永続書込を発生させない。比較測定方法は [researchdatahub-performance.md](researchdatahub-performance.md) に従う。
- 実案件で「新規性あり」などと断定せず、法的判定は弁理士レビュー・対象国/基準日/調査限界を明示。
