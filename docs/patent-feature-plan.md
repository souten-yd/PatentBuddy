# QnapPatentBuddy — 特許創出・調査・権利化支援ロードマップ

> 最優先: 出願前の発明の未公開性を維持する。既存機能は保ちつつ、専用の「発明ワークスペース」を中心に再編する。QPKG ID / 保存先 / 既存SQLite・パスキー・ポート・更新資産名は変更しない。

## 基本方針

**1) 情報分類:** 新規作成案件・ユーザーの自由入力・図面・構成要件・請求項草案・発明テーマ・検索履歴・競合比較メモ・添付PDFは、原則「機密/未出願」。公開公報の書誌事項・公表済み審査基準・公的統計は「公開候補」だが、発明に結び付けた検索式・選択理由・比較結果は機密として扱う。出願済みでも未公開の場合は機密。機密区分変更はユーザーの明示操作と記録を要する。

**2) 推論の分離:** 未公開テーマ、発明ブレスト、課題/解決手段、請求項/明細書、クレームチャート、FTO、回避設計、RAG付きチャット、文書埋め込み・クエリ埋め込み・リランクは**検証済みローカルLLMのみ**。外部AI利用はサーバーが固定した公開一般論のプロンプトなど、**ユーザーの入力・案件・履歴・ライブラリ由来の情報を含めないことをコードで証明できる操作**から段階的に解禁。OpenRouter ZDRは追加措置であり、未公開技術を送信する理由にはしない。

**3) 機密性:** スキーマ・API・UI全層でデフォルト機密、fail closed。ネットワーク向けエンドポイントのDNS・リダイレクト・環境プロキシ、ログ、メール・Webhook、外部ベクトルDB、通知タイトル、アップデータを脅威モデルに含める。非公開の発明を検索する際は、検索キーワード自体も外部送信しない。NAS外の推論機への通信は信頼できるローカル専用推論機とTLSの確認を要求。ローカルHTTPはNAS自身のloopbackのみ。

**4) 監査:** 外部送信の許可条件（送信種別/固定テンプレート/接続先種別/理由）のメタ情報だけをRAM内で記録。プロンプト本文や図面、APIキーはログ・デバッグ・監査イベントに残さない。モデル実行は明示ボタンで開始。AIの回答は提案・仮説で、請求項・明細書・証拠を自動変更しない。

**5) 法的注意:** 新規性・進歩性・権利侵害・FTOには国別・優先日・現存権利・審査経過等の判断が必要。法的な結論ではなく弁理士によるレビューを前提とする。公開前の秘匿が原則。出願前開示の例外には要件や各国差がある。

- https://www.jpo.go.jp/system/laws/rule/guideline/patent/tukujitu_kijun/ht/03_0200.html
- https://openrouter.ai/privacy

## 実装フェーズ / 依存関係

### Security Gate — 最優先（PR #12、他の新規AI機能の前提）
- すべてのLLM/埋め込み/リランクのネットワーク送信直前に機密ガード。リダイレクト/プロキシによる迂回を拒否。QnapAssistantなどのローカルAPIがクラウドに中継しないことも**管理者が明示確認**。既定では何も検証済み扱いにしない。
- 機密付き調査ジョブのニュース外部クエリ停止。自動ウォッチは公開検索語の個別承認まで送信停止。手動外部コネクタも明示承認。通知の題名/本文は汎用メッセージのみ。QdrantミラーをNAS内に制限。
- 外部AIは固定の公開一般論ガイド（「新規性」「進歩性」「権利範囲」「FTO一般論」「出願戦略」）のみ利用可能。技術内容、選択した案件、履歴、検索結果を受け取らない。
- 禁止経路テスト、誤設定テスト、更新後の移行テスト、実機でTLS/パスキー/保存先確認。

### v0.6 — 発明創出ワークスペース（ローカルのみ、最優先の次）
- **発明ブレスト**: テーマ・技術分野・現状課題・制約条件から質問を段階提示。SCAMPER/TRIZ/機能分解/逆課題/故障モード/作用効果/代替構造を用いた複数案、評価軸（効果、実施可能性、差別化、特許性の仮説）で比較。発明者が採否を承認。
- **発明提案書**: 課題→解決手段→必須構成→任意構成→作用効果→実施例→数値範囲→変形例をローカルで構造化。説明不足・サポート・実施可能性のギャップ一覧。版管理・日付・提案理由。
- **請求項支援**: 構成要件の抽出/分割、独立項候補と従属項ツリー、上位概念化、用語統一、明確性/サポート要件/新規事項追加のリスクチェック、発明群の分割出願候補。
- **根拠付きAIクレームチャート**（PR #10）: 構成要件ごと○/△/×/?、実在する行ごとの引用検証、対比文献の確認、AI結果の人手承認。安全ガード導入後にマージ。

### v0.7 — 先行技術・新規性・進歩性（ローカルRAG）
- 公開公報の正規APIから収集（検索語は公開情報と確認したもののみ）。IPC/FI/Fタームと同義語の分類式支援。引用関係・発明者/出願人・公開日・優先日による絞り込み。
- 各構成要件対比・最も近い先行文献・差異点、技術的課題・動機付け/阻害要因などの論点提示。引用の出典・段落・公報番号・日付・確信度を追跡。未知/未調査を明示。
- 権利化可能性の仮説と複数の出願方向、権利幅/実施例でのトレードオフ、回避されにくい請求項案を比較。法的判定はしない。

### v0.8 — 権利の空白・競合分析（公開統計とローカル機密分析を分離）
- 出願傾向（出願人×年代、IPC/FI、地域、優先日、権利存続、特許ファミリー）・年別増減・白地領域。データ源と欠損を明示。
- 個別テーマに関する発明・社内戦略の比較はローカルのみ。**公開済みデータだけ**の統計加工・固定の公開タスクは外部AI利用の候補。
- 回避設計: 第三者請求項の必須要件、置換/省略/変更の案、均等論等の確認項目、代替案の性能・コスト影響。意図的な侵害の助長ではなく法的リスク評価と安全な設計変更の支援。

### v0.9 — 侵害/FTO・運用監視
- 製品/構成との請求項要件対比、権利の存続・国別権利・審査経過・分割/継続・放棄/無効リスクの未確認事項一覧。○/△/×/?と引用、調査実施日、レビュー者を記録。
- 競合出願監視、継続ウォッチ、期限通知、補正前後の請求項差分。初期設定は公開検索語に限り外部へ送信し、機密はローカル検索のみ。
- 調査レポートの差分比較と履歴保存。未公開テーマに基づく外部の自動検索は禁止。

### v1.0 — 出願ドキュメント完成支援
- 発明届出書・請求項案・明細書案・要約書・図面説明文の整合、請求項番号・引用記号・実施例・サポート関係のセルフチェック。
- 証拠・変更履歴・内部レビュー・弁理士連携のエクスポート。明示承認のない外部送信、自動出願・権利判断は実装しない。

## 画面の整理
- 「発明ワークスペース」→「新規アイデア」「ブレスト」「発明提案」「請求項」「先行技術」「回避設計」「レビュー」
- 「文献管理」（旧データ）→ 公報・規格・法令・参考論文・インポート・分類
- 「特許分析」（旧分析）→ 出願人、技術分類、トレンド、空白領域、特許ファミリー
- 「競合ウォッチ」「期限管理」「公開情報ガイド」「設定 > 機密保護」の導線を明確にする。NASのRAM/ディスクを消費する処理は開始/進捗/中断/エラーを可視化。
